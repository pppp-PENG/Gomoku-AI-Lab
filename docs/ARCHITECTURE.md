# 算法与扩展约定

## 状态和价值

`Game` 保存 int8 棋盘（黑 1 / 白 -1），落子后总是换手，包括终局。输入 `[当前玩家棋子, 对手棋子, 常数1]`，不包含绝对黑白身份。Policy 对全部交叉点输出 logits，推理与训练均屏蔽占用位置。WDL 顺序固定为 `[win, draw, loss]`，相对当前行棋者；期望价值 `W-L`。

节点入边的累计 WDL 属于父节点玩家。回传前先交换 W/L，然后更新入边，逐边重复；终局叶节点的当前玩家通常是输家。PUCT 使用 `Q + c * prior * sqrt(parent_visits)/(1+edge_visits)`，没有把 prior 当成胜率。

训练根节点添加 25% Dirichlet（alpha .3），初期温度 1，随后 .1。评估及人类对战不添加噪声、按访问次数 argmax；纯 Policy 按网络概率 argmax。同值采用固定动作顺序确定性破局。

## 采样与优化

多个棋局同步推进，每棵搜索树每次提出一个叶节点，同网络叶子合批。终局样本的 WDL 按各步当时玩家与最终赢家生成。额外历史/跨架构对手模式只保存学习者所走回合。

Replay 是有界 deque，训练时随机抽样并施加同一 D4 变换于局面和 Policy 标签。损失为 MCTS 访问分布交叉熵 + 终局 WDL 交叉熵；AdamW、梯度裁剪 5、指数学习率调度。不依赖 batch normalization 的运行统计，推理和采样均 eval 模式。

断点写于完整采样/优化批次之间，保存 replay 和所有 RNG。恢复可迁移设备，但位级可复现的验收只在同一 CPU 环境成立。Transformer 默认无 dropout。

## 服务

初始化权重与完整恢复分开处理。`initial_checkpoint` / `opponent_initial_checkpoint` 分别指定新任务 A/B 的来源；`resolve_initial_models` 在创建任务前解析已登记元数据并验证规则、文件和棋盘兼容性。模型结构以所选权重自己的 `model_config` 为准，不采用来源双模型任务的另一侧结构。

`initialize_weights` 只复制源网络参数。临时加载模块使用独立的 PyTorch RNG 上下文，不改变新任务随机初始化流；重复选择同一权重只加载一次，但分别复制到两个独立目标模型。源优化器、Replay、调度器和训练进度均不导入，来源信息写入 `initialization`。完整恢复跳过这些原始来源，使用本任务快照中的完整网络和训练状态；原配置省略的来源结构也可从恢复点的配置中解析。

`paired` 模式在相同对局内交替 A/B 执棋，将每个决策样本存入实际行动模型的独立回放池，终局 WDL 始终使用该步行动者视角。双方分别优化，图表记录 `partner_*` 损失以及 `updates_b`、`a_score`、`b_score`。两份 Checkpoint 共享 `pair_id`，根模型由 `agent` 标识，`partner` 保存完整另一侧状态；从 B 恢复时重新映射到原始 A/B 顺序。

删除操作保留数据库元数据墓碑（`payload.deleted`），活动列表与模型加载排除已删除记录，物理删除对应权重文件并失效推理缓存。文件路径必须精确位于数据目录 `checkpoints/{id}.pt`。训练管理锁、评估队列锁和推理锁阻止已知活动任务与删除冲突；文件删除失败会恢复元数据可用状态。

FastAPI 同步计算路由在线程池执行。训练进程用当前虚拟环境 Python 启动，通过 SQLite 读取控制状态、写入指标。Web 持有一个受锁保护的两模型 LRU 推理缓存；评估是单独队列线程，避免阻塞 HTTP 事件循环，但会占用推理锁。生产前端和 API 同源，不依赖第三方服务或外网字体。

对局更新有 revision 乐观并发检查，AI 在计算完成后再次检查版本，防止过时响应覆盖悔棋或其他客户端更新。棋谱恢复统一调用规则引擎，拒绝重复/越界/终局后落子。

## 研究扩展接口

- 新架构：`models.build_model`，统一 `(policy_logits, wdl_logits)`。
- 新对手：`evaluation.action_for`；规则基准与网络基准分开记录。
- 新战术集：`evaluation.tactical_positions`，必须通过引擎验证标签。
- 新分析法：在 `search.analyze` 中新增具名字段，不覆盖 `win`、`policy` 或 `search_q` 的既定语义。
- 新规则：同时升级 `RULE_VERSION` 与 Checkpoint 兼容性检查；存储迁移显式升级 schema，不静默解释旧数据。

## 性能边界

目前不做全动作子局面深搜索，分析按 64 个候选一批进行 Value 推理；根 MCTS 单独计算访问和 Q。自博弈不复用上一步搜索树，降低正确性风险，代价是重复计算。实际 cProfile 和默认网络 CPU/GPU 同步延迟记录在 `validation.json`。


## 人类示范与 SFT

`demonstrations` 为 SQLite schema 1 内向后兼容的附加表，独立于 AI 对局；每份载荷另带 `schema=1` 与规则版本。所有入库请求通过同一 `Game` 引擎重放，服务端重新推导赢家并要求终局；位置预览绝不入库。规则、尺寸和完整序列的 SHA256 唯一索引使重复提交幂等。

`SFTConfig` 与 RL 配置分离，共用 `TrainingManager` 的单进程锁、实验/指标表和控制接口。`cli worker` 根据 `config.kind` 分派到 SFT 或 RL。SFT 新任务可加载任意标准 Checkpoint 的根模型（包括旧双模型 B），只复制参数；完整恢复仅接受 SFT 状态，跳过最初来源文件。

样本索引为 `(game, ply)`，包含所选整局的所有黑白步骤，在批次中重放对应前缀并生成当前玩家视角的三通道输入。策略标签为实际下一手的 one-hot，合法动作掩码后计算 CE；WDL 使用最终赢家与该步行棋者生成。输方仍是正向模仿标签。先按游戏 ID 做固定种子的整局划分，再仅对训练样本做 D4 增强，验证保持原方向且不参与梯度。

SFT Artifact 仍使用标准 `schema=1` 网络加载格式，额外标记 `training_kind=sft`。公共元数据 `sft` 记录完成轮数、训练/验证局数与手数；文件内 `sft_state` 保存棋谱快照、划分、当前轮的排列/游标、累计损失与样本数。每次更新后可暂停；恢复优化器、scheduler 和各 RNG 后从游标继续，已验证 CPU 与本机 CUDA 精确续训。保存、导入网络和重建数据索引不依赖源文件或当前数据集合。

前端分为棋谱采集和 SFT 训练两个页面，草稿与收录确认在本地浏览器持久化，正式数据由后端保存。SFT 与 RL 的完整恢复选择器隔离；普通模型选择器都可以使用 SFT 权重，并明确显示 SFT 轮数，避免将人类棋谱数误称为自博弈进度。
